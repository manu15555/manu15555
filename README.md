# Projects

# AWS RDS Multi-AZ with Bastion Host (Terraform)

## Objective

This project demonstrates building a secure and highly available PostgreSQL database environment on AWS using Terraform. The architecture includes a custom VPC with public and private subnet segmentation, a Multi-AZ RDS instance with no public exposure, and a bastion host acting as the only secure entry point to private resources.

The project focuses on Infrastructure as Code best practices, network security, least-privilege access, and Terraform configuration management.

## Skills Learned

- Building reusable Terraform infrastructure using providers, resources, variables, locals, and outputs.
- Designing AWS networking with VPCs, public/private subnets, route tables, and Internet Gateways.
- Implementing least-privilege security groups between bastion hosts and private resources.
- Deploying Multi-AZ RDS architecture for high availability and failover capabilities.
- Using bastion hosts as secure jump servers to access private networks.
- Managing sensitive variables with validation rules and Terraform best practices.
- Using data sources to dynamically retrieve AWS resources instead of hardcoding values.
- Applying Infrastructure as Code principles for scalable cloud environments.

## Tools Used

- **Terraform** — Infrastructure as Code framework.
- **AWS VPC** — Custom networking, subnet segmentation, and routing.
- **AWS EC2** — Bastion host for secure SSH access.
- **AWS RDS Multi-AZ** — Highly available PostgreSQL database deployment.
- **AWS Security Groups** — Network-level access control.
- **AWS IAM** — Access management and permissions.
- **Terraform Data Sources** — Dynamic resource discovery.
- **SSH / Key Pairs** — Secure remote access.
- **PostgreSQL (`psql`)** — Database connectivity validation.
- **AWS Provider** — Resource management in `us-east-2`.


# Importing a Lambda Function from AWS into Terraform

## Objective

This project demonstrates migrating an existing AWS Lambda environment created manually in the AWS Console into Terraform using import blocks.

The scope includes importing the Lambda function, IAM execution role, IAM policy, and CloudWatch Log Group, transitioning the infrastructure from manual management to fully managed Infrastructure as Code.

## Skills Learned

- Importing existing AWS resources into Terraform state using import blocks.
- Managing Terraform state and resolving configuration drift.
- Refactoring imported resources following Terraform best practices.
- Managing AWS IAM roles, trust policies, and permissions.
- Managing Lambda functions, source code packaging, and CloudWatch logging.
- Using Terraform data sources to avoid hardcoded values.
- Applying resource tagging and infrastructure governance practices.

## Tools Used

- **Terraform** — Infrastructure as Code framework.
- **Terraform Import Block** — Migrating existing AWS resources into Terraform.
- **Terraform Generated Configuration** — Creating initial resource definitions after imports.
- **AWS Lambda** — Serverless function management.
- **AWS IAM** — Execution roles and policies.
- **AWS CloudWatch** — Lambda logging infrastructure.
- **Archive Provider (`archive_file`)** — Packaging Lambda source code.
- **Terraform Data Sources** — Dynamic AWS resource references.
- **AWS Provider** — Resource management with default tags.
